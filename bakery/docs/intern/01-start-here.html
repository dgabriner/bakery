You already know how to program. This packet is about a program that a bakery uses while the bread is still in the oven. Read this one before you click anything.

What you are walking into

Sour Flour is a wholesale bakery in San Francisco. It bakes bread and pan dulce and delivers them to stores. Sour Flour OS is the software for that day: who gets what, what the bakers should make, what went on the van, what actually arrived, and what to bill.

It is not a website about bread, and it is not a school project that you can reset. Stores, prices, and routes in here are real. The copy you will use for learning is called Staging. It is safe from the live bakery, and it is still real enough that a careless save can confuse the people testing on their phones.

One date is the whole idea

Almost every screen asks: which delivery date? Wednesday’s order is not “the usual Wednesday.” It is that Wednesday. A baker, a driver, and a bill all have to be talking about the same date, or the store gets the wrong bread or the wrong invoice.

There are two kinds of order. Learn this before the screens.

NameWhat it meansExample
Standing order The weekly habit. It repeats until someone changes the habit. A store usually wants 12 conchas on Wednesday.
Dated order What is actually true for one calendar date. This Wednesday they want 4, because they close early.

The dated order wins for that store, on that date only. Every other store with no special note still uses its habit. Next Wednesday, the 12 comes back unless someone changes the habit. People on this project say dated beats standing, per customer. That sentence is the one to remember.

The bake day and the delivery day are not always the same day. The software still labels the work by the delivery date. Tuesday’s pan dulce bake is for Wednesday’s orders. You will feel this when a screen says “Wednesday” and the kitchen is working on Tuesday.

Words you will see

WordPlain meaning
RouteOne driver’s list of stops for a date, in order.
StopOne store on that route.
Confirm a deliveryThe driver records what the store kept, what came back, and any cash. That record becomes the bill. The price is frozen at that moment.
CODCash on delivery. The driver collects it. It is not a Square invoice.
CreditPieces the store did not keep, taken back at the door. They reduce the bill.
Finished goodsBread that is baked and counted, ready to pack or load. Not flour and not a recipe.
Commit the planA manager says “this is the bake list.” Until that happens, the baker’s screen should say the day is not committed.
Close the dayA manager records that the date is finished. The software refuses if routes or other blockers are still open.
StagingThe practice copy. Address starts with staging.sourflour.org. You belong here.
LiveThe real bakery, at bakery.sourflour.org/bake/. You do not learn on Live.

Who uses which screen

The same software shows a different home to each job. Hiding a menu is not the security. The server also checks the role. If you log in as a driver, you will only see the driver screens, and document 2 will look broken. Ask for an administrator code for this packet.

PersonWhat they open
AdministratorThe full menu, on a computer. English by default.
ManagerA phone screen: Today, Routes, Kitchen, Missed. Spanish by default.
BakerMix today, the bake list, and the pack list. Not the order book.
DriverMy Route, and Call HQ if they need the bakery. The reference for “a screen that knows its job.”
CustomerA separate portal, with their own code. You will not use that this week.

The floor often works in Spanish. You can switch the site to English. Document 2’s first working link does that for you, and the site remembers.

Staging sign-in

https://staging.sourflour.org/login.php

The sign-in page says Código para entrar. That means “code to enter.” Type the 4-digit code Danny gives you. Do not put that code in email, chat, a screenshot, or a GitHub file.

After you are in, look for the word Staging. If you do not see it, stop. You might be on the live bakery. Close the tab. The live address contains bakery.sourflour.org/bake/. Do not type your code there.

On the first walk, look. Do not save. Do not press Save, Generate, Confirm, Commit, Close the day, Send, or Reopen. Do not drag stops into a new order. Do not type into quantity boxes. Do not check boxes on the pack list. Those actions write, and other people are using this copy.

Opening five pages also prepares missing orders for the coming week: the Operations Dashboard, Daily Run, Daily Orders, Daily Production, and Mix Today. That does not erase an order someone already edited. It is still a write. Document 2 warns you again at those steps.

Names on the screens are real stores. Read them so you understand the day. Do not copy them into a portfolio, a class assignment, or a public repository.
